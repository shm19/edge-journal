## P0

### P0-1. `saveIdea` mishandles stale or foreign scenario ids
`src/lib/actions.ts:70-80`, `:83-96`

The upsert loop does `tx.update(scenarios).set(s).where(id = sid AND ideaId = ideaId).run()` and then unconditionally pushes `sid` into `scenarioIds`, without checking that a row was updated. Consequences:
1. A scenario deleted in another tab: the update is a silent no-op, the scenario is lost, and `scenarioIds` still contains the dead id. If a mistake is linked to it (`scenarioIndex`, line 92), the insert at `:85` writes `scenario_id = <dead id>` and the whole transaction fails with an opaque `FOREIGN KEY constraint failed` (surfaced to the user by the catch at `:133-135`).
2. A scenario id that belongs to a different idea (tampered payload or a stale form): the update is skipped by the `ideaId` guard, but the mistake is then linked to the other idea's scenario. Cross-idea link; its cost then reads that scenario's R.

Fix: use the `changes` count from `.run()`. If 0, either insert as a new scenario (and use the new id) or throw `"A scenario was changed in another tab, reload"`. Add a DB-backed test for both cases (see P1-6).

### P0-2. Mistake cost: sign bug, double counting and hidden partial totals on the headline card
`src/app/(app)/page.tsx:170`, `src/lib/queries.ts:149-158`, `:374-390`, `src/app/(app)/ideas/[id]/page.tsx:169`

1. **Sign bug.** The dashboard prints `−{g.cost.toFixed(2)}R`. A negative total (the mistake "saved" R, which the editor and idea page both support, `idea-editor.tsx:692`, `ideas/[id]/page.tsx:184`) renders as `−-1.00R`. The sort at `queries.ts:389` also puts it last, which is right, but the label is wrong.
2. **Double counting.** Cost of a linked mistake is `alternative R − primary R` (`queries.ts:149`). Two mistakes linked to the same alternative (e.g. "Moved stop to BE" and "Early TP" both measured against "Hold to target") each get the full delta, so the idea total (`ideas/[id]/page.tsx:169`) and the dashboard per-type totals can exceed what was actually lost on the trade. Same-trade costs are not additive.
3. **Partial totals.** `mistakeSummary` adds only known costs (`:381-384`), but the dashboard shows the sum as if complete; `costKnown < count` is never shown. The row says `−3.00R ×5` when only 1 of 5 has a cost.
4. **Two implementations.** The editor re-implements the cost (`idea-editor.tsx:1099-1111`, `rDelta`) separately from the server (`queries.ts:149`). They already differ in one detail: the server nulls the link when the scenario is gone (`:156`), the editor does not.
5. **Dead data.** `tradeR` and `ideaIds` are computed in `mistakeSummary` (`:375`, `:380`, `:385`) and never read anywhere (grep confirmed).

Fixes:
- Add `mistakeCost(dir, alt, primary)` to `stats.ts` (pure), use it from both the server and `rDelta`.
- Format with a shared signed helper (`fmtR(-g.cost)`), never prefix a literal `−`.
- Decide and document the rule for overlapping links: simplest is "idea-level cost = max over linked mistakes, per-type rows show each mistake's own delta and are labelled 'not additive'". Alternative: only allow one linked mistake per alternative (validate in `ideaSchema`).
- Show `n of m measured` when `costKnown < count`.
- Delete the unused fields.
- Add tests: sign, partial, overlap, unlinked, open primary (see P1-6).

### P1-1. Idea detail page does the whole-DB load three times; `getIdea` is not targeted
`src/app/(app)/ideas/[id]/page.tsx:16`, `:22`, `:27`; `src/lib/queries.ts:88-141`, `:175`

- `getIdea(id)` filters only the `ideas` table (`queries.ts:90`). It then reads **all** setups, tags, scenario types (`:93-95`), all `idea_tags` (`:99`), all `scenarios` (`:110`), all `attachments` (`:127`), all `mistake_types` (`:134`) and all `idea_mistakes` (`:136`), and filters in JS with `ids.has(...)`.

Fix (small):
- Add `where(eq(scenarios.ideaId, id))`-style filters when `where.id` is set (or `inArray(..., ids)` for lists); keep the full scan only for the list pages.
- Wrap `getIdea` in React `cache()` so metadata and page share one result.
- Replace the neighbour lookup with one SQL query: `select id from ideas order by coalesce(closed_at, opened_at) desc, id desc` (matches the JS sort at `queries.ts:172`), or `where` on the two neighbours with a row-value comparison.
- Keep `loadIdeas()` for list/analytics pages: for a personal journal it is fine up to a few thousand ideas. Note the ceiling in `docs/architecture.md` (not measured).

### P1-2. Missing foreign-key indexes
`src/db/schema.ts:76-89`, `:99-110`, `:118-130`, `:132-141`; `drizzle/*.sql` (only the three `*_name_unique` indexes exist)

SQLite does not index foreign keys. Without indexes:
- `scenarios.idea_id`: scanned by `saveIdea` (`actions.ts:66-68`) and by every `ON DELETE CASCADE` from `ideas`.
- `idea_mistakes.idea_id`, `idea_mistakes.mistake_type_id`, `idea_mistakes.scenario_id`: scanned on save, on idea delete, on mistake-type delete, and on scenario delete (the `SET NULL` rule).
- `attachments.idea_id`: scanned on save and on idea delete.
- `idea_tags`: the composite primary key `(idea_id, tag_id)` covers lookups by `idea_id` only. Lookups by `tag_id` (cascade on `deleteTag`/`deleteTagGroup`, the usage count in `settings/page.tsx:15-22`) scan the table.
- `scenarios.scenario_type_id`: scanned by `deleteScenarioType` (`actions.ts:251-254`) and the settings usage count.
- `ideas.setup_id`: scanned by `ON DELETE SET NULL` on setup delete.

Fix: add in `schema.ts` via the third `sqliteTable` argument, e.g. `index("scenarios_idea_idx").on(t.ideaId)` for each column above, plus `index("idea_tags_tag_idx").on(t.tagId)`; `npm run db:generate`; commit the migration. Zero behavioural risk.

### P1-5. Closing a trade stamps `closedAt = now`, which skews every date-based stat
`src/components/idea-editor.tsx:73-80`

Typing an exit price on the primary scenario sets `closedAt` to the current time when blank. Most journal entries are written after the fact, and imported/backdated backtest, skipped and forward ideas get "closed today". Because `date = closedAt ?? openedAt` (`queries.ts:169`) drives the equity curve order, streaks, drawdown, the month dimension, the dashboard ranges and the "last 7 days" tile, the numbers shift silently until the user notices and edits the field. The field is editable but nothing prompts for it.

Fix: do not auto-stamp. Instead, when a closing exit is entered and `closedAt` is blank, default it to `openedAt` and show it as "Closed (UTC) = opened, adjust if different"; or keep "Now" only on the button. Reopening ("Still open", `:1025`) should also clear an auto-set `closedAt`.

### P1-11. Session hardening: fail-open defaults
`src/lib/session.ts:10-15`, `src/app/login/actions.ts:45`, `:42`

- If `SESSION_SECRET` is missing/short and `NODE_ENV !== "production"`, a **publicly known** secret is used (`session.ts:14`). The Docker image sets `NODE_ENV=production`, but any other start (`next start` under a process manager that does not set it, a mis-set env) yields forgeable session cookies. Fail closed: allow the fallback only when `NODE_ENV === "development"`.
- `COOKIE_SECURE` is parsed as `... === "true"` (`login/actions.ts:45`): any value other than the exact lowercase `true` (`True`, `1`, `yes`, a typo) turns the `Secure` flag **off**. Use `process.env.COOKIE_SECURE !== "false"` combined with the production default, so only an explicit `false` disables it.
- Tokens are stateless, 30 days, `sub` fixed, and `logout` only deletes the cookie (`login/actions.ts:52-56`). A copied cookie stays valid until expiry; the only kill switch is rotating `SESSION_SECRET`. Cheap improvement: put a `sessionVersion` in `settings`, embed it in the JWT, bump on logout-everywhere; or shorten to 7 days.

### P1-12. Server actions redirect on expired session, losing unsaved edits
`src/lib/auth.ts:22-24` used by every action

`requireAuth()` calls `redirect("/login")`. Inside `saveIdea` that navigates the client away from a half-written editor (the unsaved-changes guard, `idea-editor.tsx:100-107`, does not fire for router navigations). After 30 days or a secret rotation the next save throws away the entry. Fix: in actions use `if (!(await isAuthenticated())) return { ok: false, error: "Session expired, sign in again in another tab, then save" }`; keep `redirect` for pages.

### Security hardening (all low risk for a single-user app behind Caddy)
- **Login throttle** (`login/actions.ts:9`, `:26`, `:36`): keyed on the **leftmost** `x-forwarded-for` value, which a client can set when the proxy appends instead of overwriting (nginx `$proxy_add_x_forwarded_for`; the README documents only Caddy, which overwrites). The map is never pruned and grows with each distinct key; state is lost on restart; lock is 60 s flat. Use the rightmost entry added by your proxy (or `x-real-ip`), prune expired entries, add a small global cap, and use escalating locks (60 s, 5 min, 30 min). Add the proxy requirement to `README.md`.
- **Security headers** (`next.config.ts`): none are set. Add `headers()` for `X-Frame-Options: DENY` / `frame-ancestors 'none'`, `Referrer-Policy: same-origin`, `X-Content-Type-Options: nosniff`, and `poweredByHeader: false`. A strict CSP is awkward with Next inline scripts; start with the framing and referrer headers.
- **Defense in depth for reads.** Only the layout and the proxy gate page reads (`(app)/layout.tsx:8`, `proxy.ts`); `loadIdeas`/`getIdea` and the pages call no auth function. Layouts are not re-rendered on soft navigation, so the proxy is the real gate. Currently correct; add `await requireAuth()` (or an `isAuthenticated` assert) to `loadIdeas`/page entry points so a future matcher change in `proxy.ts:24-26` cannot expose data.
- **Uploads** (`api/uploads/route.ts:23-34`): the 10 MB check relies on `Content-Length`; a chunked body is fully buffered by `formData()` before `file.size` is checked, and there is no total storage cap. Authenticated-only, so low risk. Cap with a streamed size count if it ever matters.
- **Markdown** (`bits.tsx:84-91`): `react-markdown` without raw HTML is safe (and `javascript:` URLs are stripped by default), but `![](https://...)` in notes loads an external image on view (IP/referrer leak). Add `urlTransform` to allow only relative and `data:` images if the journal text ever includes pasted content.
- **Cookie**: name it `__Host-ej_session` in production (needs `Secure`, `Path=/`, no `Domain`, all already true) to prevent subdomain cookie injection. Optional.

## Tips

1. Do the changes in this order: P0-1 and P0-2 (small, test-first), P1-2 (indexes, one migration), P1-4 step 1 (file split) which unlocks P1-6 (tests), then P1-3, P1-1, P1-8 as behaviour-neutral refactors guarded by those tests, then P1-7.
2. Write the DB-backed test harness once (temp `DATA_DIR`, `server-only` alias, `next/headers`/`next/cache` mocks). Every later action/query test is then a few lines.
3. A tiny `fixtures.ts` (`makeIdea({ status, r, mistakes })` building `IdeaView` objects without a DB) makes the pure analytics tests trivial and fast.
4. Keep "use server" and route files to handlers only; every helper you want to test (`safeNext`, `sniff`, `csvCell`) should live in `src/lib`.
5. Add a test that iterates `IDEA_STATUSES` and `EXIT_REASONS` and asserts the label maps and bucket helpers cover every value; this turns the AGENTS.md "decide where it's counted" reminder into a failing test.
6. Type the label maps with `Record<IdeaStatus, string>` (and the others) so a new enum value is a compile error rather than a missing label at runtime.
7. When the DB grows, the order of fixes is: targeted `getIdea` (P1-1), indexes (P1-2), paging (P2-15), formatter cache (P2-14). Only then consider SQL aggregation; `loadIdeas()` in memory is a reasonable design for this size.
8. `CHECKPOINT.md` says Step 3 is a review step: record this file's triage (apply, defer, reject) there per `docs/workflow.md` stage 4, and tick P0 items off first.
